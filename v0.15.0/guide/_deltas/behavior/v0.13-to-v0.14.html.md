- v0.14 ships `py.typed`, so type checkers now read pyDeprecate's own types instead of treating every object as `Any`. Runtime behavior is unchanged; only checker output moves.
- **`Old: DeprecationProxy[New] = deprecated_class(target=New, ...)(Cls)` no longer type-checks.** A call-form `deprecated_class(...)` alias is typed as the class it forwards to (`type[New]` with a class `target`, otherwise the wrapped class), so drop the annotation. `DeprecationProxy[T]` remains the annotation for `deprecated_instance()` proxies.
- **Old names accepted only through `args_mapping` / `attrs_mapping` are reported on call-form aliases** as `call-arg` / `attr-defined`, as the decorator form already did under mypy. To keep such call sites type-checking during the migration window, keep the old names in a legacy class body (decorator form) or wrap the alias in `cast(DeprecationProxy[New], ...)`; `isinstance` against the alias then stops type-checking.
- **Proxy-only attributes** such as `__wrapped__` and `__deprecation_config__` are invisible on `type[New]`. Read them with `get_deprecation_config(Old)` or `inspect.unwrap(Old)`.
- Setting `__deprecated__` on a deprecated proxy now keeps the marker on the proxy, and deleting it no longer removes the wrapped object's own marker; reading it after deletion raises `AttributeError`. `copy.copy`, `copy.deepcopy`, and `pickle` keep a PEP 702 message written onto the proxy.
