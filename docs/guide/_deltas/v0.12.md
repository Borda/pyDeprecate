**In v0.12** — here is what changed that you might have missed:

- **`@deprecated` on a class is now first-class supported.** Applying `@deprecated` directly to a class used to emit a warning threatening `TypeError` in a future release; that threat is retired. It now dispatches to `deprecated_class()` and produces an identical `_DeprecatedProxy`, emitting a one-time informational notice (`` `@deprecated` on class `MyClass` now dispatches to `@deprecated_class`. ``) fired at most once per class per process, keyed by module + qualified name. The dispatch is permanent; only the notice is removed, in v1.0, and it is suppressed by `stream=None`. Prefer `deprecated_class()` directly — same result, no notice, and required to reach class-only options such as `attrs_mapping`. See [`@deprecated` on a class](classes.md#deprecated-on-a-class) for a runnable example.
- **`TargetMode.AUTO` resolves an omitted `target`.** `TargetMode` gained a fourth member, `AUTO`, now the default value of `target` on the `@deprecated` front door (previously `TargetMode.NOTIFY`). It is a decoration-time fallback, not a runtime mode: an omitted `target` resolves to the mode implied by the rest of the configuration before the wrapper or proxy is built, and the resolved mode — never `AUTO` itself — is stored in `DeprecationConfig`. On a function, `args_mapping={...}` resolves to `ARGS_REMAP` and no mapping resolves to `NOTIFY`; on a class, a mapping resolves to `ARGS_REMAP` and no mapping to a warn-only proxy (`target is None`). The practical win: `@deprecated(args_mapping={"old": "new"})` previously fell into `NOTIFY` and was flagged misconfigured — now it infers `ARGS_REMAP` and applies the mapping. `AUTO` is front-door-only; the strict forms keep explicit defaults (`deprecated_callable()` → `NOTIFY`, `deprecated_class()` leaves `target` unset) and both raise `TypeError` on `target=TargetMode.AUTO`. Prefer an explicit `target` — you never write `TargetMode.AUTO` yourself.
- **Explicit `TargetMode.NOTIFY` with a mapping is never silently overridden.** Passing `target=TargetMode.NOTIFY` together with a mapping remains a misconfiguration on every path: a `UserWarning` fires at decoration time (`TypeError` in v1.0), the mode stays `NOTIFY`, the mapping is inert, and audit metadata flags the wrapper `misconfigured`. Omit `target` when you want the mapping applied. There is consequently no single-proxy way to get a blanket "warn on every access" notice while a mapping is also active — stack two `deprecated_class()` layers (inner `ARGS_REMAP` / `ATTRS_REMAP`, outer `NOTIFY`); see [Nested proxy wrappers](classes.md#nested-proxy-wrappers).
- **`deprecated()` slimmed to common arguments only.** The front-door dispatcher now exposes only the arguments common to both dispatch shapes: `target`, `deprecated_in`, `remove_in`, `stream`, `num_warns`, `message_template`, `args_mapping`, `args_extra`, `skip_if`, `update_docstring`, and `docstring_style`. The class-only option `attrs_mapping` raises `TypeError` on the front door — use `deprecated_class(attrs_mapping=...)` directly. `message_template` and `skip_if` passed through `@deprecated` on a class are now forwarded to the proxy (`message_template` used to be dropped silently).
- **`template_mgs` → `message_template`.** The custom-notice parameter was a typo (`mgs` for `msg`) and is now `message_template` on `@deprecated`, `deprecated_callable`, `deprecated_class`, and `deprecated_instance`; the old name works as a deprecated alias until v1.0 (passing both raises `TypeError`). Audit code reading `__deprecated__.template_mgs` keeps working through a read-only alias, but the stored field is now `message_template`. Separately, `deprecated_module()` renames its `message` argument (append semantics) to `message_template` (replace semantics) with no deprecation window — `message=` now raises `TypeError`, as `deprecated_module` was unreleased.
