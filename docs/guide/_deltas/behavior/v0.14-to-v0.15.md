- **Calls that need no forwarding preserve the caller's positional and keyword argument form.** A call that needs no forwarding, rename or extra argument reaches the source exactly as made.
    - A call forwarded to a callable target is passed by keyword. The exceptions are positional-only parameters and surplus `*args`, which stay positional.
    - A custom stream that raises no longer leaves warning bookkeeping or emission context stuck. On a deprecated proxy, a warning that fails to deliver does not spend the warning budget. A decorated function still spends it.
- **Warnings that reported a pyDeprecate frame now point at the caller.** Call-time warnings already named the user's call site. The remaining ones, notably the inner warning of a stacked deprecation chain, now carry the caller's line and module too. A warning filter keyed on `module="deprecate"` that matched those warnings no longer does. Those warnings therefore surface, and raise under `-W error`. Key filters on the calling module instead.
- **Async proxy warnings are emitted when the underlying awaitable or async iterator is obtained.** A later failure or exhaustion during `await` or `__anext__` still consumes the warning budget.
    - If the warning itself fails, a coroutine the wrapped call created is closed. A coroutine the wrapped object holds as an attribute, or is itself, is left usable.
    - `next()` on a deprecated proxy now warns before the wrapped iterator advances, so a failed warning consumes no item. Calling the proxy also warns first, as `@deprecated` does. Other synchronous operations still warn only after success.
    - In-place operators and `defaultdict` subscripts keep their effect if delivery fails.
- **A custom `stream` is called exactly once, with its signature read before the call.** A stream that declares `**kwargs` receives `stacklevel=` and must accept or drop it. Forward it to `warnings.warn` or `logging.warning`; `print(msg, **kwargs)` raises `TypeError`. Declare `def sink(msg)` to receive the message alone. A bare `(*args, **kwargs)` `functools.wraps` pass-through is judged by the callable it wraps, also when a `functools.partial` binds it. A stream whose only parameter is named `stacklevel` receives the message alone.
- **`skip_if` now covers item and in-place writes.** With `skip_if` active, `proxy[key] = value`, `del proxy[key]` and in-place operators write to the wrapped object. The read-only guard does not apply. A fatal proxy (`as_exception=True`) raises `DeprecatedError` before a subscript, iteration or mapped attribute read touches the wrapped object.
- **Deprecated generators warn on the first iteration, not at the call.** A deprecated generator function keeps `inspect.isgeneratorfunction`. A deprecated async-generator function keeps `inspect.isasyncgenfunction`, so pytest `yield` fixtures run their setup and teardown. The warning, the `num_warns` budget, `skip_if`, argument binding and an `as_exception` / `as_exceptions()` error now resolve on the first `next()` / `__anext__()`. A generator that is never iterated never warns. Move `pytest.warns()` and `pytest.raises()` around the first iteration, and keep `as_exceptions()` active at that step.
- **An empty-string `args_mapping` value keeps the argument.** Under `@deprecated`, `args_mapping={"old_arg": ""}` now passes `old_arg` through under its old name, as `deprecated_class` always did. A `**kwargs` target therefore receives it; only `None` drops an argument. Map the argument to `None` if you relied on `""` dropping it.
- **Proxies carry only the protocols of the wrapped object or its replacement.** A deprecated `dict` is no longer `callable()`, an `Iterator`, `os.PathLike`, `Awaitable` or `AsyncIterable`. A protocol the object disables stays disabled. `type(proxy) is _DeprecatedProxy` is now `False`; use `isinstance(proxy, DeprecationProxy)`. The generated proxy subclasses cannot be pickled by reference.
- **Forwarding to a `classmethod` checks the source's shape at decoration.** Any receiver name works (`klass`, `mcs`).
    - These source shapes raise `TypeError` at decoration:
        - A source with no leading positional parameter raises the error.
        - A source with a later parameter named like the target's receiver raises the error.
    - A static or plain source given a non-class first argument raises `TypeError` before warning.
- **CLI arguments follow `argparse`.**
    - Spellings only the Fire-based CLI accepted exit `2`:
        - A quoted literal such as `--version '"0.10"'` exits `2`.
        - A list literal in `--exclude` exits `2`; pass comma-separated patterns.
        - A table in `--min-grace` exits `2`; set it in `pyproject.toml`.
        - `--path=pkg` exits `2`.
        - Short flags such as `-r` exit `2`.
        - An empty `--report-json=` exits `2`.
        - Abbreviated option names exit `2`.
        - A second positional path exits `2`.
    - A boolean flag given a value accepts only `true`, `false`, `1` or `0`. Use the bare flag or `--no-<flag>` otherwise.
- **CLI exit codes changed.** `check` and `all` exit `1` on misconfigured targets and inner-order `@property @deprecated` wrappers, which used to pass. A scan error or internal error exits `3` instead of `1`, and `--exit-zero` masks neither `2` nor `3`.
    - These inputs exit `2`:
        - A single `.py` file exits `2`.
        - A directory holding several packages exits `2`.
        - A name that is neither a path nor an importable module exits `2`.
    - Check how CI steps treat `2` and `3`.
- **`deprecated_module(stream=None)` warns at the call.** An explicit `stream=None` still delivers through `warnings.warn` but emits a `FutureWarning`. In v1.0 it silences the module warning, and the `num_warns` default changes from `-1` to `1`. Omit `stream` for today's delivery and pass `num_warns=-1` to keep a warning on every access.
- **`DeprecationWrapperInfo.empty_mapping` and `identity_mapping` warn with `FutureWarning`.** Reading the deprecated aliases now emits `FutureWarning` on every access instead of `DeprecationWarning`, and raises under fatal mode. Read `empty_args_mapping` and `identity_args_mapping` instead.
